# Research and implementation decisions

The font continuation corrected an earlier assumption: the canonical spacing fixture has no `w:sz` in docDefaults or its default Normal style. Installed Word 16.0 build 4627 supplies 10pt; it was not inherited from an explicit Normal size. [The OOXML font-size definition](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.fontsize?view=openxml-3.0.1) leaves the application choice open when the entire hierarchy omits a size, so 10pt is a pinned Word compatibility decision. The importer now resolves text and paragraph-mark fonts separately and keeps that choice in the disposable reading copy. A second Word-saved authored fixture exercises 14pt paragraph ancestry, an 18pt character override, 20pt direct text and 24pt/30pt paragraph marks. Browser computed size/family is compared with native COM; font availability is distinct from line-box/baseline equivalence.

The raw font-cascade fixture reproduced the first-save horizontal difference: 21 glyphs in an untouched wrapped paragraph shift by about 0.123pt while text and vertical/page positions agree. Its native SaveAs splits the run before word24 and inserts `w:lastRenderedPageBreak`. This is an observed structural difference and a lead for further isolation, not proof of the complete rendering cause. The raw case remains reproducible; no pixel tolerance was widened. The Word-saved fixture is a separate native-authored starting point.

Line-spacing semantics and metrics (September 10): [OOXML](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.spacingbetweenlines.line?view=openxml-3.0.1) uses distinct automatic multiples and physical minimum/exact amounts. Native Word omits its default Single value when saving, so importing absent automatic spacing as the app's 1.65 default was incorrect and is now fixed. Mixed Arial 10/20pt runs expand minimum/automatic lines while exact lines stay fixed. The rule/authoring/migration dependency is implemented; variable font-driven pagination remains open. [Contract and reproduction](parity/contracts/W-MODEL-SECTIONS.md).

A raw generated fixture exposed an approximately 0.123pt horizontal glyph shift after native first-save normalization in an untouched paragraph. An explicit [OpenType flag](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-docx/116847ff-9af6-45a7-a21f-0e0ff2eef41d) did not resolve it. That experiment was removed. The spacing-edit oracle now also uses a Word-saved authored baseline, while the raw-producer mismatch remains recorded as a separate unresolved compatibility case. No runtime source settings are rewritten to match the native save. Fixture provenance/regeneration: [tests/fixtures/README.md](../tests/fixtures/README.md).

Widow/orphan and empty-line research (September 10): installed Word changes an exact-spaced 14-line paragraph from 13/1 to 12/2 when widow control is enabled, and moves an eight-line paragraph off a single-line orphan split. This agrees with [Microsoft's line/page-break guidance](https://support.microsoft.com/en-us/word/line-and-page-breaks). A terminal hard break after 13 lines leaves the paragraph-end caret on page 2. Anchoring the actual paragraph to that empty fragment lets Chromium's real trailing BR retain the caret, while earlier fragments move back to their original pages. Browser keyboard/pointer edits and actual exports are independently compared. [Contract](parity/contracts/W-MODEL-SECTIONS.md).

The next metrics dependency must distinguish exact from minimum physical spacing and automatic multiples. [OOXML spacing](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.spacingbetweenlines?view=openxml-3.0.1) defines automatic spacing in 240ths of a normal single line and inheritance when properties are omitted. The current unitless CSS multiplier and explicit physical exact values cannot represent every native font/minimum-line calculation. Do not simply enable the exact-spacing paginator for these paragraphs; measure native mixed-font line boxes and preserve the spacing rule before broadening it.

Exact-spacing overflow research (September 10): the installed Word fixture places 13/7 hard-break lines across its first two pages, moves an eight-line kept paragraph to page three and wraps a following paragraph across pages three through five. Its final section starts on page six. CSS paragraph line-height alone did not reproduce the fixed grid because inline metrics enlarged line boxes; the implementation now controls inline leading under the exact paragraph grid. A stricter browser Range check found that BR elements needed ProseMirror-owned span wrappers to move their geometry with text fragments. [Native procedure, source links and remaining typography limits](parity/contracts/W-MODEL-SECTIONS.md).

Mixed-section layout research (September 10): [ProseMirror node decorations](https://prosemirror.net/docs//ref/#view.Decoration.node) support view-only positioning while preserving one document/selection owner. [OOXML section types](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.sectiontype?view=openxml-3.0.1) distinguish the default next-page break from continuous/odd/even/column starts; unsupported types remain continuous in the first measured short-flow path. [Named CSS pages](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/page) print distinct page sizes using the same resolved section geometry. Local Word comparison verifies exported files and page rectangles/text; it does not establish exact browser typography or paragraph fragmentation. [Implementation evidence and continuation](parity/contracts/W-MODEL-SECTIONS.md#historical-handoff-mixed-section-surfaces).

September 10 live Word boundary continuation: a typed current boundary state now moves/removes section endings through editor transactions and repairs retained header/footer inheritance. Native split/join exports match all tested semantic properties. A PDF comparison initially exposed approximately 0.037 pt of glyph placement difference after the native inserted space; explicit repagination did not resolve it. Reopening the native saved DOCX before rendering, as already done for the browser export, produced exact pixels on all three pages. This distinguishes saved-file compatibility from native in-memory editing. The [OpenType compatibility flag](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-docx/116847ff-9af6-45a7-a21f-0e0ff2eef41d) was investigated; explicitly pinning it did not fix the mismatch, and that experimental fixture change was removed. [Scope and receipts](parity/contracts/W-MODEL-SECTIONS.md).

September 10 Word section-range continuation: the installed Word reference keeps both paragraph fragments before a section break after a split; deleting that break merges the text under the following section's geometry. The latter agrees with [Microsoft's documented deletion behavior](https://support.microsoft.com/en-us/word/delete-a-section-break). ProseMirror source-paragraph IDs are copied by an ordinary split, so immutable paragraph identity alone cannot represent edited section boundaries. The current mapper diagnoses ambiguous boundaries, and the writer rejects the known duplicate-boundary corruption. A live break representation is required next. [Contract, browser tests and native reproduction](parity/contracts/W-MODEL-SECTIONS.md).

September 10 programme baseline: read-only executable inspection confirms x64 Office 2016 on this PC: Word 16.0.4627.1000, Excel 16.0.4627.1001 and PowerPoint 16.0.4266.1001. [Baseline and hashes](parity/BASELINE.md). The [research index](parity/SOURCES.md), [browser equivalents](parity/BROWSER_EQUIVALENTS.md) and [engine plan](parity/ENGINE_PLAN.md) define how to convert the existing catalog into detailed implementation contracts. Family requirements and unassigned command records are pending research, not completed behavioral specifications.

## Totals activation correction

Native Excel comparison of six direct-entry exports found that formula entry below the table enables its totals row. That row is excluded from structured data sums and restores the original Total label. The implementation now stores and patches totals labels/custom formulas explicitly. Microsoft describes totals as a separate table row with function choices in [Total the data in an Excel table](https://support.microsoft.com/en-us/excel/get-started/total-the-data-in-an-excel-table). Implicit activation details are native observations, not claims established by that article. [Scope and reproduction](EXCEL_TABLE_ENTRY.md).

September 9 automatic table-entry follow-up: Microsoft's [direct-entry expansion guidance](https://support.microsoft.com/en-us/excel/resize-a-table-by-adding-or-removing-rows-and-columns-in-excel) informed the workflow. Native probes found that occupied neighboring cells prevent expansion, replacement in the entered cell can expand, and formula-triggered expansion activates a totals row (with supported retained labels/custom formulas). The implementation follows these measured distinctions. [Scope and reproduction](EXCEL_TABLE_ENTRY.md).

September 9 calculated-table resize follow-up: Microsoft's [Resize Table workflow](https://support.microsoft.com/en-us/excel/resize-a-table-by-adding-or-removing-rows-and-columns-in-excel) informed the UI. Native probes establish that added blank cells use the master despite existing exceptions, existing destination data remains intact, and excluded current-row references evaluate to `#VALUE!`. Clearing the last body value removes the master. Seven actual browser export stages have independent native comparisons. [Scope and reproduction](EXCEL_TABLE_RESIZE.md).

September 9 calculated-column follow-up: Microsoft's [entry/update workflow](https://support.microsoft.com/en-us/excel/use-calculated-columns-in-an-excel-table) and [exception guidance](https://support.microsoft.com/en-us/excel/detect-formula-errors-in-excel) informed the command. Native probes established filling above/below the entry, relative-reference anchoring, hidden-row inclusion and the rule that existing values or exceptions stop propagation. Eight browser exports have independent cell/master-formula comparisons. [Scope, reproduction and limits](EXCEL_CALCULATED_COLUMNS.md).

September 9 direct-header and international-name follow-up: Microsoft's [heading entry](https://support.microsoft.com/en-us/excel/get-started/set-up-your-header-row), [default headings](https://support.microsoft.com/en-us/excel/turn-excel-table-headers-on-or-off) and [structured references](https://support.microsoft.com/en-us/excel/using-structured-references-with-excel-tables) informed the workflow. Native range-copy experiments established that duplicate normalization reserves later explicit suffixes and repairs swapped column identities simultaneously. Native name experiments verified Unicode/backslash identifiers and exposed the distinction between internal and display names. [Scope, locale mapping and evidence](EXCEL_TABLE_HEADERS.md).

September 9 table renaming follow-up: Microsoft's [structured-reference rules](https://support.microsoft.com/en-us/excel/using-structured-references-with-excel-tables) inform escaping and repair of table/column identifiers. Native Excel experiments verify three browser export stages and distinguish literal strings, OOXML name tokens and explicit table selectors. The native fixture uses defined names for validation/conditional rules after Excel rejected direct structured references there. [Implementation, evidence and remaining limits](EXCEL_TABLE_RENAMING.md).

September 9 Excel tables follow-up: Microsoft's [table creation](https://support.microsoft.com/en-us/excel/get-started/create-and-format-tables), [resizing](https://learn.microsoft.com/en-us/office/dev/add-ins/excel/excel-add-ins-tables) and [OOXML table metadata](https://github.com/OfficeDev/open-xml-docs/blob/main/docs/spreadsheet/working-with-tables.md) informed the shared model/package commands. Native inspection identified a mismatched ExcelJS default-theme marker, worksheet element ordering in the table/note fixture, and integer HLS rounding differences. These are experimentally established findings. [Implementation, reproduction and limits](EXCEL_TABLES.md).

September 9 Excel structural follow-up: Microsoft's [insertion/deletion workflow](https://support.microsoft.com/en-gb/excel/get-started/insert-or-delete-rows-and-columns-in-excel), [deleted-reference behavior](https://support.microsoft.com/en-US/Excel/how-to-correct-a-ref-error) and [SpreadsheetML formula documentation](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/working-with-formulas) informed the package repair design. Independent native Excel comparisons exposed two details corrected during implementation: literal hyperlink destinations remain unchanged, and inserted cells inherit adjacent validation even beyond its previous range boundary. [Implementation, native evidence and limits](EXCEL_STRUCTURE.md).

September 9 Excel validation follow-up: [Microsoft's workflow](https://support.microsoft.com/en-US/Excel/get-started/apply-data-validation-to-cells) and [existing-value behavior](https://support.microsoft.com/en-us/excel/more-on-data-validation) distinguish rule assignment from validating later input. Original range metadata now supplies blank-cell rules without eagerly allocating full columns. Native Excel verifies the browser export's relative survivor formula, full-column list rule, metadata and 14 numeric/list validation decisions, then renders PDFs. [Reproduction and remaining limits](EXCEL_VALIDATION.md).

## Mode landing and font support follow-up

The user requested a simple mode selector instead of a platform dashboard. The landing now contains Word, Excel and PowerPoint cards; saved-file management moves into the Open dialog. The canonical task list is [TASKS.md](../TASKS.md) at repository root.

- [Fontsource SvelteKit guide](https://fontsource.org/docs/guides/svelte) and [installation guide](https://fontsource.org/docs/getting-started/install): font packages can be bundled with Vite. We bundle variable Inter, Source Serif 4 and JetBrains Mono locally, with normal/italic Latin faces and their OFL notices. No runtime CDN is used.
- [MDN CSS Font Loading API](https://developer.mozilla.org/en-US/docs/Web/API/CSS_Font_Loading_API): FontFace can load binary ArrayBuffer data and register a validated face in document.fonts. The local-font workflow uses this API and waits for IndexedDB commit before indicating success.
- [Tiptap font-family/size documentation](https://tiptap.dev/docs/conversion/content-types/text-and-formatting/font-family-size) and the installed TextStyleKit source: font family, size and line-height are available in the open-source editor extensions. Paragraph-level line spacing is implemented separately to apply to the paragraph instead of only a span. Family names are quoted to preserve names containing standalone digits.
- Installed Mammoth `lib/documents.js`, `lib/options-reader.js` and `lib/document-to-html.js` show direct run font/fontSize in its intermediate tree but no default HTML font mapping. `docx-typography.ts` supplies bounded run style mappings and decorates the resulting spans before sanitization. This preserves direct properties, not full theme/style inheritance.
- [Mammoth source and transformation documentation](https://github.com/mwilliamson/mammoth.js): transformations and style maps are the extension point used for that direct-run import behavior. The regression suite covers basic DOCX/XLSX/PPTX typography round trips; independently authored Office fixtures remain required for parity claims.

Unresolved font portability: the native backup model stores font names but not the separate local font library. Full embedding, script coverage, per-glyph fallback diagnostics and cross-platform text metrics remain unchecked tasks. See [font support boundaries](FONTS.md).

## Documents and Office packages

## Existing PowerPoint edits and placeholder inheritance

Microsoft documents slide-placeholder inheritance through the matching layout `idx`; the importer now follows that mapping instead of placing missing-transform placeholders at the origin. Layout-to-master geometry uses placeholder type. The external WithMaster and SampleShow decks exposed the overlap through actual browser editing. [Microsoft placeholder implementation notes](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/3ec954b2-37a6-41da-8973-04a592c91fb2), [python-pptx primary implementation documentation](https://github.com/scanny/python-pptx/blob/master/docs/user/placeholders-understanding.rst).

Presentation text belongs to drawing paragraphs/runs, and notes live in related notes-slide parts. These structures support targeted edits without rebuilding unrelated charts, layouts or media. The implementation retains untouched runs and part payloads, adds notes/image relationships when needed, and reports unsupported edits. Two browser exports were opened in native PowerPoint and rendered to PDF, including first notes on a deck without a notes master. This is empirical evidence for those files, not complete PresentationML conformance. [Microsoft slide text documentation](https://learn.microsoft.com/en-us/office/open-xml/presentation/how-to-get-all-the-text-in-a-slide-in-a-presentation), [notes-slide documentation](https://learn.microsoft.com/en-us/office/open-xml/presentation/working-with-notes-slides), [scope and reproduction](PPTX_PRESERVATION.md).

## Complete ribbon catalog baseline and Home commands

The user supplied the German desktop Word ribbon. Microsoft's [Office Fluent UI command catalog repository](https://github.com/OfficeDev/office-fluent-ui-command-identifiers) provides tab, group, parent-menu and control identities, including contextual and backstage commands. Revision `b230a0df45036b2d5e8b49ebf368b3f90ada8d63` was downloaded with Git blob and SHA-256 verification. All named Office 2016 Word/Excel/PowerPoint rows are retained in [the generated inventories](ribbon/README.md), with Microsoft's MIT notice. This is a concrete versioned acceptance baseline, not proof of behavior or coverage of newer features.

[Format Painter](https://support.microsoft.com/en-us/word/use-the-format-painter), [case conversion](https://support.microsoft.com/en-us/Word/change-the-capitalization-or-case-of-text) and [formatting marks](https://support.microsoft.com/en-us/word/show-or-hide-tab-marks-in-word) informed the new Home subset. Tests verify the supported browser/model/export behavior, while paragraph/graphic painting, complete language-sensitive casing and the remaining full commands stay open.

## Financial calculations and explicit document/image transforms

[Microsoft PV](https://support.microsoft.com/en-us/excel/functions/pv-function), [PMT](https://support.microsoft.com/en-us/excel/functions/pmt-function), [IPMT](https://support.microsoft.com/en-us/excel/functions/ipmt-function) and [EFFECT](https://support.microsoft.com/en-us/excel/functions/effect-function) informed the financial extension. The implementation is independently checked against 170 authored native Excel cases; these cover timing, invalid domains and coercion details beyond ordinary examples. Integer numeric strings avoid dependence on the German installation's decimal separator. See [financial evidence](EXCEL_FINANCIAL.md).

The [WordprocessingML break definition](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.break?view=openxml-3.0.1) distinguishes type and clearing behavior. Explicit page breaks now remain inline in their original paragraphs; a reading-copy annotation carries them through semantic import. A browser workflow verifies a two-page PDF, while native Word layout remains unverified. [DrawingML Transform2D](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.transform2d?view=openxml-3.0.1) supplies image flip attributes; the actual browser export's flags and rotation are checked in native PowerPoint and rendered to PDF. Group/text/shape transforms and crop semantics remain separate unfinished work.

## Paragraph controls and statistical edge cases

Word indentation and pagination controls use WordprocessingML paragraph properties, backed by [Microsoft indentation documentation](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.indentation?view=openxml-3.0.1), [character-unit override notes](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/138732dc-507a-4164-af66-808c2fd9f2f9) and [keep-with-next semantics](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.keepnext?view=openxml-3.0.1). The implementation uses native paragraph properties for DOCX and CSS constraints for browser printing; those are not equivalent layout engines. The inherited hanging-to-first-line conversion remains explicitly unsupported.

The [STDEV.S reference](https://support.microsoft.com/en-us/excel/functions/stdev-s-function) and [statistical function inventory](https://support.microsoft.com/en-us/excel/statistical-functions-reference) informed the scalar extension. Rather than relying solely on prose, 114 exact formulas were evaluated in installed Excel. That revealed differing fractional-rank handling in SMALL/LARGE, first-encountered MODE ties and function-specific empty/coercion errors. [The receipt and limits](EXCEL_STATISTICS.md) bind these observations to the tested build.

## Imported editing and aggregate semantics

Microsoft's [slide-reordering guidance](https://learn.microsoft.com/en-us/office/open-xml/presentation/how-to-move-a-slide-to-a-new-position-in-a-presentation) uses the existing slide-ID list rather than rebuilding slides. The implementation follows that structure and verifies the actual browser download in native PowerPoint; section-dependent moves remain guarded.

The [COUNT reference](https://support.microsoft.com/en-us/excel/functions/count-function) distinguishes directly supplied values from references and ignores ordinary errors. The [SUM reference](https://support.microsoft.com/en-us/excel/functions/sum-function) documents reference handling. A 128-case native Excel receipt verifies the implemented coercion, INDEX references, empty/formula-empty cells and errors, including correction of two old expectations. [Aggregate evidence](EXCEL_AGGREGATES.md) documents scope and limits.
