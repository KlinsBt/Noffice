Test assets retain their upstream rights and are excluded from Noffice's MIT grant and static build.

## Reproduce

```powershell
npm.cmd run corpus:download
npm.cmd run build
npm.cmd run corpus:test
npm.cmd run corpus:report
npm.cmd run corpus:gate
```

Only the downloader needs network access. It verifies byte sizes and pinned Git blob hashes, records SHA-256 receipts, and saves inputs under `.local/office-corpus/input/`. The browser tests use the static build, block external requests, save source-view/reimport screenshots, export unchanged and edited documents, and reimport edits. `.local/office-corpus/results/` retains all review artifacts. `REPORT.md` and `report.json` summarize package inventories, text-token losses, structural decreases and mixed Strict/Transitional SpreadsheetML errors. Run the report after tests finish.

`corpus:gate` is intentionally stricter than workflow tests and currently **exits 1**. It detects missing/incomplete edited evidence and preservation loss signals. The remaining failures are explicit in the report: the extreme-nesting input is safely rejected and therefore has no export, and the protected workbook's initial cell has no edit evidence. There are currently zero counted losses in produced edited exports. The gate has not been relaxed to turn those missing results green. A green browser workflow means its specified operations succeeded, not that every input feature works. Package-count decreases are review signals; legitimate part renaming can also produce them. Zero counted decreases is not visual or calculation certification.

## Results and fixes, 2026-09-08

The first run had 57 successful workflows, three import failures, 18 byte-identical unchanged exports and 39 edited exports with loss signals. The fixes address:

- ExcelJS rejecting valid icon filters in tables. A separate parsing copy omits unsupported filter metadata; original filters and conditional formatting remain in the retained export package. Their full browser editing/evaluation is still missing.
- Date-validation formulas such as cell references being coerced to NaN. Import now reads original validation formula text.
- Excessive DOCX nesting causing a stack overflow. Preflight rejects XML deeper than 256 levels or above 500,000 elements, and excludes DTD/entity declarations before recursive conversion.
- Unchanged DOCX/PPTX reconstruction dropping advanced features. A SHA-256 fingerprint of the imported editable content now allows exact original-byte export and survives native backups.
- Added PPTX text boxes destroying existing charts and layouts. When the only changes are added text boxes, rectangles or ellipses, the writer patches slide XML in the original package. Existing objects, timings, media, masters, slide size and relationships remain. The subsequent retained-edit implementation also patches supported existing text, direct formatting, geometry and notes, plus image additions. Unsupported imported structural changes now fail explicitly; see [PowerPoint preservation](PPTX_PRESERVATION.md).
- New XLSX nodes using Transitional namespaces inside Strict documents. Cells, values, styles and workbook metadata now use their source namespace; a dedicated unit test and corpus audit cover this boundary.
- Edited DOCX reconstruction dropping headers, notes, review structures, images and section metadata. Mapped paragraphs now patch their original XML; unknown parts remain. Shared Tiptap normalization prevents automatic table/HTML changes from becoming unintended source edits. Supported text, selected formatting, paragraph spacing/direction and footnote edits have separate unit/browser tests. [Word preservation](DOCX_PRESERVATION.md) documents the implementation and remaining limits.
- DOCX fonts and emphasis defined through styles being omitted from the browser view. The reading copy now resolves document defaults, paragraph/character style ancestry, toggle properties and Latin theme font references. This remains a partial style cascade.

Current corpus workflows: **59 imports and unchanged byte-identical exports, one expected safe rejection, and 58 edited exports/reimports**. One protected workbook's initially selected cell is deliberately not edited. All 60 manifest browser scenarios pass these stated expectations. The latest full run also passes three existing-PPTX text edits, totaling **63 passing browser scenarios**. The **19 DOCX edited loss-signal cases are resolved for the tested paragraph additions**: the report now finds **zero** missing parts, text-token decreases, counted feature decreases or Strict namespace issues in the edited exports. Arbitrary editing and full desktop functionality remain unchecked.
