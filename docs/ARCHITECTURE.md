# Architecture

Flat list section breaks retain one semantic list and split only its paragraph/item. Live section endpoints may sit inside a qualified flat list. Numbering decorations derive suppressed empty ending markers without saving display counters. Retained DOCX export preserves numbering definitions; fresh section extraction retains enclosing list wrappers. Source-backed list marker metrics and container pagination/print/PDF are still required. The bookmark adapter moves only the uniquely validated collapsed Word navigation anchor at a plain insertion offset; it does not generalize bookmark editing.

`word-paragraph-layout-commands.ts` validates partial semantic patches and shares paragraph selection/history with spacing commands. Svelte controls do not own formatting semantics. Story measurement derives left/available width and per-line paint origins; these values only enter disposable screen/print trees, never persistence or DOCX attributes. Physical-indent numeric input matches the measured ±1,584pt native range; rendering qualification stays bounded separately. Compatibility-dependent justified line planning remains open.

Paragraph range selection is shared by Before/After and line-spacing commands through `word-paragraph-selection.ts`. Line-spacing edits validate the whole request before applying one history event; mixed and unchanged values are resolved from semantic attributes. Body and story controls share `WordLineSpacing.svelte`; custom story options remain within the existing story modal. Guarded variable-line story paint uses the independently measured paragraph-origin grid while retaining semantic line heights and zero Before/After. Its native references, failed initial output and current verification are bound in [the active contract](parity/contracts/W-TEXT-UNIFORM-LINES.md#current-executable-handoff).

Qualified spaced single-line Arial10/exact40 stories now use `word-story-grid.ts` for independently measured printer-origin and after-spacing paint rounding. `word-story-measure.ts` marks only fully qualified story copies; semantic paragraph margins, total story height, original bytes and history remain unchanged. Screen paragraphs paint from measured absolute local origins to avoid accumulating ordinary-flow rounding. Physical print/PDF fragments consume the same origin. The original56 spacing workflows and224 direct-PDF pages pass; new36 edit/reimport workflows pass, with native export/return and broader acceptance in progress. This finite profile does not qualify other fonts, wrapping, scripts, backgrounds or larger paragraph spacing. [Current evidence](parity/contracts/W-TEXT-UNIFORM-LINES.md#current-executable-handoff).

Qualified short measured Word body paragraphs retain their source screen rectangle while printing through the same physical fragment clone used by direct PDF. Their named print pages carry zero margins because fragment coordinates already include document margins. Browser PDF text extraction and paper dimensions remain separate acceptance gaps.

Word body and story font controls read aggregate selection values through the pure `word-selection-font.ts` helper. Mixed size/family values are independent; selected inline text and tabs determine the displayed value, while mark-only selections use paragraph formatting. Explicit size entry commits on Enter as well as change. `word-font-commands.ts` preserves unrelated inline attributes and avoids unchanged paragraph/inline history steps; repeated commits remain undoable as one actual edit. Native aggregate queries and browser/export acceptance are recorded in the active pagination contract, whose wider scope remains incomplete.

Body and story superscript/subscript commands use mutually exclusive semantic marks, retaining nominal font sizes in storage and DOCX. `word-script-metrics.ts` holds independently captured Arial10/20 exact40 view profiles and Arial10 Single profiles for bounded uniform unwrapped text lines. Qualified Single script wrappers suppress their own extra inline leading; the nominal paragraph strut supplies the native line height. Tabs and hard breaks retain their separate qualification. The story dialog shares the font-line engine and document typography rules with the page view, so editing uses the same measured script size. Native script paint uses measured6.48/12.96pt sizes while stored10/20pt sizes stay nominal. The line engine derives glyph size and baseline decorations; the print clone and direct PDF consume those same measurements. Unqualified script contexts retain explicit PDF rejection. No measured script pixels are serialized into the document. This bounded implementation remains under full interaction and exported-file verification.

`paragraphScript` records paragraph-mark formatting separately from inline script and nominal fonts. `paragraphScriptsVersion` identifies the import/migration semantics without affecting content fingerprints. Recovery hydrates only paragraph metadata from retained originals; ambiguous edited paragraph identities reject safely. Qualified empty-paragraph typing and selected terminal-mark replacement participate in ordinary history. Body and story editors retain typing-run identities for native-compatible DOCX export. Script tab fields use the same derived measurement profile as visible runs; only measured Arial10 exact40 dot leaders are qualified.

Page, line and tab decoration updates synchronize a pending native DOM selection before replacing view wrappers. A browser arrow event can precede ProseMirror's selectionchange notification; repaints must preserve that caret instead of restoring the older model selection. Controlled real-key tests exercise this timing during zoom and verify subsequent typing and undo/redo in body and story editors.

Failed legacy Word hydration exposes its actual cause when DOCX/PDF export or Print is attempted. Original-file and full-model backup downloads remain available, and opening a valid document clears the recovery state without requiring a page reload.

Word font-feature metadata preserves the independently inherited `w14:ligatures` and `w14:cntxtAlts` switches in runs and paragraph marks. A bounded bit mask maps to explicit browser font features; omission resolves to the measured disabled default. Fresh and retained DOCX writers carry those settings. Legacy uniform edited text and unchanged mixed text recover the missing metadata; changed mixed text rejects with working backup recovery before mutation. Copied and created stories resolve their original/template provenance. PDF shaping groups compatible typography within one paragraph and measured line, crossing edit-session and color spans as independently observed in Word. Each Unicode cluster retains its first origin and first character color; tabs and incompatible features interrupt the group. Font acquisition stays per physical face, while embedding is bounded to32 feature variants. Fully embedded fonts retain their complete bytes and receive CID widths and Unicode mappings from the actual emitted clusters, including ligatures. Each CMap block is bounded to100 entries; ambiguous CID/text identities reject. Embedding restrictions remain enforced. Context-dependent glyphs that cannot be encoded independently still reject. Five boundary workflows and30 actual PDF pages pass; broader glyph acceptance remains open in the active contract.

For measured exact40 paragraphs, mixed font descriptors can share baseline paint only if every baseline-aligned run independently resolves to the same native baseline. Actual per-run browser font metrics position those glyphs; unknown descriptors retain the guard. Times20 has a measured dot profile only.

Word leader cells use independent physical-page geometry and finite native font profiles. The tab remains one semantic character; pseudo-element ink, measured widths and baseline decorations stay outside stored content. Body and story views receive an explicit page-left origin, and story measurements are keyed by part, width and origin. ProseMirror may place atom decorations on an inline fragment wrapper, so tab measurement, baseline and surface code resolve the same paint box. A zero-leading tab's box supplies its inline baseline when its invisible text has no usable glyph rectangle. The tested single-line leader paragraphs can enter page-fragment layout; wrapping and unmeasured tabs remain guarded. Print clones preserve fractional body origins in transforms. Direct PDF emits validated measured leader cells at the native baseline. Font embedding keys include face identity; the producer permits the tested Arial 10pt bold/italic faces only, obtains actual local files and rejects missing or unmeasured styles. Leader ink remains separate from semantic tab integrity checks.

Literal Word RGB values are retained through disposable reading styles without modifying source bytes. `runColorsVersion` is migration metadata excluded from content fingerprints. Unchanged legacy snapshots restore colors from retained originals; edited legacy snapshots keep their earlier reading semantics and export against the corresponding legacy baseline. This avoids interpreting an old importer omission as an intentional color removal. Theme and automatic-color resolution remain separate requirements.

Paragraph-mark kerning is retained separately from text runs and materialized on empty/terminal typing in the same history event. Legacy body and original/copied/generated stories recover missing values from retained provenance; explicit zero and edited text survive. Version-only metadata is excluded from content fingerprints. Nested typing-session spans inherit retained kerning, and metadata-only spans remain parseable. Measured wrapped text uses per-line baselines, including authored spaces, even when font glyph bounds overlap adjacent rows.

Header/footer section deletion repairs live references, copied/generated parts and per-section options in the same ProseMirror history transaction (`word-story-section-repair.ts`). For the measured leading-section removals, Word transfers the nearest section with independent stories as a group; slots inherited from an older owner become styled blank parts. `docx-empty-stories.ts` derives those templates from the retained built-in header/footer style cascade using the same paragraph-reading decorator as import. Missing templates migrate additively from the original file without replacing edits or storage revisions. Generated blank parts keep distinct paragraph identities and use the ordinary retained paragraph editor; original package parts remain untouched. Missing built-in paragraph/character styles are created privately with collision-safe IDs and native-measured tab/spacing defaults; empty slots are exposed by the existing story editor. Typing or unlinking materializes all six first-section roots, including inactive stories. Missing style roots and whole styles parts now use collision-safe synthesis and OPC registration. Virtual native defaults distinguish absent containers from present empty ones; retained XML is unchanged by import. Template version4 and styleDefaultsVersion1 migrate unchanged/compatible legacy content, while ambiguous edits get a backup/original recovery screen. Fresh story authoring now uses the distinct authored-body identity and existing atomic story history; its export and full creation acceptance are under verification.

Word header/footer stories live in an optional versioned `WordContent.stories` model, separate from body HTML and immutable source section references. `word-story-source.ts` validates internal OPC relationships and retains aliases/inactive parts; `word-story-reading.ts` rebases disposable reading copies for bounded Mammoth conversion. Import/backup sanitization covers every story; legacy hydration preserves edited body content/revisions. Text, page options and link commands use atomic document attributes in the body editor's undo history. Optional section page overrides retain first-page/distances separately from source XML; odd/even selection remains global. The retained writer tracks settings-only changes independently from body XML.

It applies final effective section references after live section movement. Identity collisions and invalid provenance reject before producing an export. Imported empty-slot authoring and the measured link/clone paths have model/history/browser coverage; current native actual-file acceptance remains explicit in the contract. [Exact tested scope](parity/contracts/W-TEXT-UNIFORM-LINES.md#current-executable-handoff).

The current91-page comparison is pixel-identical to prior output while recovering extracted wrap spaces. Native glyph/print differences remain explicit. Broader story creation, reference/options authoring, nonzero story spacing and the complete interaction matrix remain open. ## Product boundary

Noffice is an independent, browser-only office workspace distributed under MIT.
The landing page selects Word, Excel, or PowerPoint mode. File management lives in an Open dialog; editing occupies the full window.
Desktop Word, Excel, and PowerPoint parity is the long-term target, not the status of this initial implementation.

## Runtime

- Svelte 5 with SvelteKit and TypeScript.
- `@sveltejs/adapter-static` generates `build/`, with `index.html` as the SPA fallback.
- Root layout disables SSR. There are no server routes, actions, databases, or document-processing services.
- The HTML entry point is `src/app.html`, not a root Vite `index.html`.
- Dependencies are bundled locally. File parsing and downloads use browser APIs.
- Static HTTP hosting is required; opening the build via `file://` is not a supported module-loading environment.

## Storage design

`noffice-workspace` version 1 contains `files` and `versions` stores. Files carry a monotonically increasing persistence revision. A readwrite transaction reads the stored revision, checks the expected revision, and writes the updated file and version together. Completion, not request success, marks a save successful.

The UI debounces writes and serializes pending snapshots. Switching apps does not discard a pending save. Stale tabs cannot overwrite newer revisions. The last 20 saves are retained per document, and restoring one creates a new save. Trash is reversible. Downloaded backups are still necessary because browser storage can be cleared or evicted.

Initial library loading merges the stored snapshot with files already imported or edited in the mounted workspace. Current in-memory files and revision counters take precedence over the delayed snapshot. A browser regression holds the initial IndexedDB response until after an import/edit/save, then checks completion and reload.

## Interoperability

`.noffice` is the native JSON backup format. Its version is explicit and unknown versions must be rejected. It preserves the supported model and, when present, original Office bytes.

DOCX uses Mammoth for semantic import and docx for newly created document export. Imported documents use `docx-preserve.ts`: `docx-import.ts` annotates paragraphs in a disposable reading copy, `docx-styles.ts` resolves supported inherited properties, and `word-extensions.ts` supplies the shared editor/export normalization. Text/formatting changes patch mapped original paragraphs; unrelated parts remain byte-identical. Unsupported structural changes fail explicitly. See `DOCX_PRESERVATION.md` for scope. PPTX uses a bounded OOXML reader and PptxGenJS writer. Browser editing/rendering remains partial.

`office-preservation.ts` fingerprints imported DOCX/PPTX editable content with stable SHA-256 input ordering; native backups retain the fingerprint. Unchanged exports return original bytes. DOCX XML complexity is checked before recursive conversion. `pptx-import.ts` resolves source slide/object identities, placeholder geometry and slide proportions. `pptx-preserve.ts` patches supported existing text/direct formatting/geometry/notes and adds simple objects and images with new relationships. Unrelated part payloads remain intact. Unsupported imported structural edits fail explicitly. New decks use PptxGenJS. See `PPTX_PRESERVATION.md`. A successful original-byte round trip does not imply complete import/rendering support.

The downloaded corpus, scripts and Office/PDF tools are development-only. Inputs, exports and screenshots live in ignored `.local/office-corpus/`; no corpus files or native Office automation enter `build/`. See `OFFICE_CORPUS.md` for source provenance, measured failures and desktop evidence.

XLSX import combines ExcelJS with original OOXML metadata. Each imported sheet retains its source part path. Export reimports the retained original to establish a baseline, then patches supported changed cells, styles, dimensions, and visibility in that package. Unchanged workbooks return the original bytes; untouched ZIP entries in edited workbooks retain their uncompressed bytes. Unknown parts and relationships remain present. Supported whole-row/column operations create retained package checkpoints with reference repair; unsupported sheet/anchor changes reject explicitly. New workbooks use ExcelJS generation and retain their existing sheet operations. Imports created before source-part mapping must be reopened from their original XLSX.

The formula engine builds a dependency map for direct references during export. Names, structured references and INDIRECT are conservatively marked affected after value edits, then ordinary downstream dependencies are propagated. Supported affected caches are replaced; unsupported caches remain and the workbook requests full recalculation. Imported table metadata lives in the sheet model and is checked by the preservation writer. Parsed expressions, cell results/errors and lookup positions are memoized for a workbook snapshot. This is not a complete incremental Excel engine. See [calculation evidence and limits](EXCEL_CALCULATION.md). View virtualization uses actual row heights and stable row keys; frozen-row views currently mount all visible rows. Browser scroll anchoring is disabled for the virtual grid so row-window updates do not move the selected cell.

The reference repository informed revision checks, transaction completion handling, separation of format models, and retention of original packages. No MPL implementation is copied. See `RESEARCH.md` for specific reviewed files and public primary sources.

`aggregate.ts` consumes values with reference/blank/error provenance. `word-tab-bars.ts` derives bar positions from semantic paragraph stops without requiring literal tabs. Body page backgrounds use physical fragment rectangles; continuous and story paragraphs use derived CSS shadows. A scaled unit-width shadow preserves thin ink through Chromium's print quantization. Short bar-bearing sections also use disposable fragment print trees. Direct PDF consumes the same measured line-box offsets with a bounded drawing count. Tab field measurement enforces its 1,000-tab work limit before serializing or probing fields. Detached field probes share one contained holder; their widths are cached by immutable paragraph identity and resolved font styling. Font loading, zoom and explicit layout refresh invalidate that cache. The line engine reuses ephemeral Ranges and waits for measured tabs before assigning native baselines. Tab layout allows at most 32 changing passes per content/font/width revision; exhaustion restores ordinary editable tabs and leaves uncertain PDF layout unsupported. This bounds recovery work without certifying wrapped-tab placement. Validated unchanged Word originals can be downloaded byte-for-byte without waiting for print layout, while changed exports retain layout and stale-content checks.

`financial.ts` owns constant-period annuity, depreciation and nominal/effective rate algorithms; the evaluator supplies scalar coercion and error propagation. `word-page-break.ts` stores page boundaries as inline atoms to keep source paragraph mapping intact; import annotations, both DOCX writers and browser print styling retain their meaning. Slide image flip flags are optional model properties for backward compatibility, applied inside the rotated image frame in the canvas and around its center in SVG previews. Retained exports patch transforms without rewriting media.

The unequal-column foundation retains one editable paragraph with view-only fragment displacements. `word-column-reflow.ts` reconciles semantic line ranges with the allocator by visual line ordinal; a disposable DOM font probe measures eligible uniform ASCII word/space text at the assigned column width. Cycles and bounded-work exhaustion reject the plan. Mixed font metrics, additional formatting boundaries, broader scripts, punctuation and oversized words still need broader shaping acceptance. Hard breaks terminate their existing reflow line instead of adding an inline-block row. Column separators derive from occupied columns and the actual section end. Fragment print trees use physical paper boxes and zero-margin named print pages, keeping hanging spaces from triggering browser print shrinkage or blank overflow pages. Hard-line struts quantize cumulative boundaries at the declared canvas zoom.

For eligible reflow exports, `WordExportLayout` carries settled semantic column offsets and a complete content binding to the independent DOCX adapter. It is ephemeral: no layout geometry enters document HTML, history or storage. The exporter rejects a stale binding, normalizes plain runs, then splits them at current column boundaries while preserving text and run properties. Native Word Save regenerates these boundaries; they affect first-open PDF advances even when fonts are identical. Removed explicit font marks resolve to the paragraph font. Native acceptance compares the same edit/save/reopen/restore sequence; initial browser print remains compared with the initial native source. See the active pagination contract for current evidence and remaining limitations.

Selected Word Grow/Shrink uses `stepWordFontSize` in the independent font command layer: validate the full range, step each effective run size, change paragraph marks only when selected, preserve unselected inherited atoms, and apply one history event. Both body/story toolbars share the command. Mixed caret semantics remain a separate unresolved acceptance dimension; the existing caret fallback is not certified by selected-range results.


The fresh section writer postprocesses only its generated `word/document.xml`: `docx-authored-sections.ts` validates section counts and paragraph ordinals, moves each packer-generated `sectPr` onto the existing ending paragraph, then removes the redundant empty marker. Imported ZIP parts continue through the retained writer. The fragment planner preserves empty ending paragraphs semantically while sharing the preceding last line in the measured compatible continuous single-column case; entering text restores normal flow. The measured regular Arial40/exact24 single-line path uses a paint transform and keeps the semantic line index at zero; unmeasured oversized wrapping still rejects pagination.

Fresh packages also set `w:embedTrueTypeFonts` through `docx-authored-fonts.ts`, retaining the bundled Inter payload when Word subsequently saves the document.
