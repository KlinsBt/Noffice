# Browser equivalents and their acceptance boundaries

The default product remains static, client-side and usable offline. The mechanisms below are researched options, not newly implemented functionality. Each must become a tested contract in S-STORAGE, S-AUTOMATION, S-NETWORK or its app family. IndexedDB provides transactional structured storage; OPFS provides origin-private file storage; neither supplies Word layout, Excel calculation or a Windows object model automatically. [IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API), [OPFS](https://developer.mozilla.org/en-US/docs/Web/API/File_System_API/Origin_private_file_system).

| Desktop capability                          | Proposed browser implementation                                                                                                                                   | Required proof / observable difference                                                                                                                                                |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Save, recovery and document library         | IndexedDB transactions, revisions, journals/checkpoints; optional OPFS blob store; persistent-storage request where available                                     | Crash/quota/eviction/reload tests; original and backup recovery; storage eviction is not silently treated as permanent disk durability                                                |
| Open/save directly to a folder              | User-selected File System handles, handle persistence and renewed permission; file input/download fallback                                                        | Browser/permission-denial matrix, external changes and conflict detection; no arbitrary path access or guaranteed lasting permission                                                  |
| Large calculation and conversion engines    | Dedicated workers; transferable data and revision IDs; locally bundled WASM where benchmarks justify it                                                           | Cancellation, timeout/memory pressure and determinism; WASM does not provide native OS privileges                                                                                     |
| VBA and document automation                 | Bounded interpreter/compiler plus explicit Word/Excel/PowerPoint document object adapters and command transactions                                                | Language, events, UDFs and object semantics tested against authored macros; preserve originals; unsupported host APIs remain differences. JS scripting alone is not VBA compatibility |
| COM/ActiveX/add-ins                         | Browser extension modules using a capability-limited API and equivalent document/form controls                                                                    | Reimplement required user outcomes; existing Windows binaries are not directly usable. List each unsupported automation/API contract                                                  |
| Databases and external workbook connections | User-selected local snapshots/workbooks, bundled relational/query processing, explicit refresh; optional permitted direct fetch for eligible sources              | Refresh and query semantics, credentials/CORS behavior, offline snapshots and error states; no native driver assumed and no runtime service introduced silently                       |
| Real-time collaboration                     | Local operation log/conflict resolution; explicit peer sessions via WebRTC where feasible; manually exchanged connection information as a service-free experiment | Concurrent edits, identity/conflict/reconnect behavior; arbitrary-network connectivity and persistent hosted presence are not guaranteed without signaling/relay infrastructure       |
| Clipboard/Paste Special                     | Clipboard API plus paste events and internal rich formats; permission-aware fallback                                                                              | Office-to-browser and reverse formats, trusted gestures, denied permissions, selection/undo; no promise of unrestricted clipboard access                                              |
| Print and PDF                               | Deterministic layout/PDF generation plus browser print UI                                                                                                         | Native geometry/page ranges/notes and paper comparison; browser-controlled printer dialogs and silent printing remain differences                                                     |
| Mail merge and send/share                   | Local recipients, document generation, downloadable bundles and explicit OS share/email handoff where supported                                                   | Correct generated documents; actual delivery requires separate authorization/service. A draft/download is not a sent message                                                          |
| Fonts, proofing, dictation/media            | Bundled permitted fonts/dictionaries/models and user-selected assets; local media processing where feasible                                                       | Font metrics, language accuracy, permissions, offline execution, codec and model limits; do not invoke remote speech/proofing unnoticed                                               |

File System access depends on explicit user permission and browser support. Handles can be stored in IndexedDB, but that does not guarantee a future permission grant. [File System API](https://developer.mozilla.org/en-US/docs/Web/API/File_System_API). Clipboard access likewise has security and interaction requirements. [Clipboard API](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard_API).

Workers move computation away from the UI and WASM can host compiled engines; the app still needs the full algorithms and document semantics. [Workers](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers), [WebAssembly](https://developer.mozilla.org/en-US/docs/WebAssembly/Reference/JavaScript_interface).

WebRTC still requires exchanging connection information; manual exchange is a proposed fallback to investigate, not evidence of reliable internet-wide collaboration. Record any STUN/TURN/signaling dependency before adopting it. [MDN signaling](https://developer.mozilla.org/en-US/docs/Web/API/WebRTC_API/Signaling_and_video_calling).

## Completion policy

- [ ] Prototype each required equivalent and measure supported outcomes across the browser matrix.
- [ ] Compare the user workflow and saved document with native Office.
- [ ] Document permissions, offline behavior and exact differences before verifying it as an equivalent.
- [ ] Keep unresolved compatibility requirements in the ledger. Never turn an approximate alternative into an exact-parity claim.

The instruction to pursue equivalents authorizes technical implementation/research, not sending documents to external accounts or adding a server requirement. If a result cannot fit the product constraints, retain the unsatisfied requirement and pursue the best locally achievable subset with explicit evidence.
