# P-MODEL-INHERITANCE: retained placeholders, rich text and groups

## Identity and scope

PowerPoint / S-MODEL, **partial**, with no whole-command ownership. This is the imported-document prerequisite for P-TEXT, P-MASTER and P-DRAW. Related catalog controls include `FontSize`, `SlideLayoutGallery` and `ViewSlideMasterView`; this contract does not certify those commands or introduce a master editor. Native reference: installed PowerPoint 2016 x64 **16.0.4266.1001**, checked against `baseline.json` before automation.

Implemented subset: retain the source slide/layout/master/theme chain, placeholder identity and group ancestry; resolve the tested Latin character properties through run/paragraph/list/master/theme defaults; render mixed runs on the canvas, thumbnails and slideshow; preserve their styles through the tested text replacement, inherited-position edit, history and persisted reload. Native master/layout editing, reset, full group-coordinate rendering/editing and native text layout remain open.

Research (September 10, 2026): Microsoft documents [master/layout identities and relationships](https://learn.microsoft.com/en-us/office/open-xml/presentation/working-with-slide-masters), [custom layouts](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.customlayout) and [placeholder shapes](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.shapes.placeholders). Those structural references guide the resolver; the installed application supplies the concrete font/geometry and replacement expectations below.

## Behavioral specification

1. Import the authored two-slide `powerpoint-inheritance.pptx`. Each slide belongs to a different master/layout. The title has no direct transform or font size. Layout 1 supplies 60pt/30pt/560pt/85pt geometry, 38pt size and italic; Layout 2 supplies 72pt left and 40pt size. Both resolve the major Latin theme font to Calibri Light, black, centered. Browser model units scale the 720pt width to 960 units. These values are independently measured after native save/reopen, not inferred from the browser importer.
2. Each subtitle contains `Plain BOLD tail`. The first run is underlined 20pt Arial; the second is bold 28pt Arial without underline; the last is italic 20pt Arial with RGB #112233. All 30 source characters across the two subtitles retain their measured properties. CSS underline must be applied on each run, since a parent underline cannot be canceled by a child with `text-decoration: none`.
3. Move the first title from 80 to 96 browser X units (60 to 72 native points), preserving the remaining inherited transform dimensions. Replace its text with `Master 1 title edited`. Undo/Redo restores geometry and text through the existing immutable history.
4. Replace `BOLD` with `BRAVE` through the object text input. Retain the replaced run's bold 28pt formatting. The old writer inserted replacement text into the preceding run at a run boundary; it now distinguishes a replacement from a zero-length boundary insertion. Native `Characters(7,4).Text='BRAVE'` is the independent replacement oracle. Undo/Redo, saved reload and actual exported/reimported PPTX retain the result.
5. The unchanged export is byte-identical. After edits, every package payload except `ppt/slides/slide1.xml` remains byte-identical. Master/layout/theme and relationship parts, the second slide, and nested group structures remain retained. Two native-reopened edited slides match the independent native edits in shape identity/design/layout, geometry and every text character property, then in their native-rendered PDFs at 144 DPI with no pixel tolerance.
6. Legacy snapshots without `textModelVersion` are hydrated from retained source bytes. Properties still equal to the former import projection adopt the corrected effective values; distinct text/style edits, IDs and revisions remain intact. An unchanged legacy snapshot still exports the original bytes. Hydration is idempotent, writes no IndexedDB revision and cannot overwrite a concurrently replaced workspace object. Historical edits explicitly set equal to the old import default cannot be distinguished from untouched values; this ambiguity is not claimed solved.
7. Group ancestry and source affine transforms are retained. The measured nested rectangle/ellipse frames resolve through scale, translation, outer rotation and horizontal reflection. Moving/resizing tested unrotated non-text leaves inside orthogonal groups writes inverse local coordinates, including measured outer rotation/reflection. Child rotation/reflection changes, text and skew remain guarded before history and independently at export. Invalid paragraph levels and singular group extents reject. These errors leave original bytes unchanged.
8. In the existing two-slide authored fixture without notes, enter the first speaker notes, undo/redo, reload, insert a local image and export/reimport. Create and register one notes master and its own theme copy, then reuse them for further notes slides. The original theme payload and any same-directory asset relationships are copied unchanged; existing theme/master/slide/chart content is preserved. A broken theme target rejects instead of claiming a successful export. Native PowerPoint reopens the actual combined output, verifies notes/image/chart/dimensions and renders its PDF. This is notes-text/package interoperability, not native notes-page design/print parity.

### Native regression findings

The existing first-notes writer omitted the notes master when the source had none. Adding a master that shared `ppt/theme/theme1.xml` with the presentation still caused an E_FAIL in the pinned native build. An isolated package with a distinct, byte-identical theme part opened successfully. `ensureNotesMaster` now creates that separate theme relationship. [Microsoft's notes/master part relationships](https://learn.microsoft.com/en-us/office/open-xml/presentation/structure-of-a-presentationml-document) describe the graph; the separate-part requirement here is an observed native implementation constraint, not a claimed universal OOXML prohibition.

The sandbox independently prevented native embedded-image loading and stalled a direct PNG insertion probe. The same authored image-flip deck opens and verifies outside it. Native image checks therefore require the approved unsandboxed execution environment; a failed sandbox open is not recorded as a passing compatibility test. Only the identified hidden PowerPoint instance created by the stalled probe was stopped. No user documents were opened. Reduced diagnostic packages remain under `.local/pptx-validation`; they are not accepted export artifacts.

## Model and implementation

`pptx-text.ts` resolves Latin run attributes individually, including explicit false booleans, theme major/minor font names and paragraph alignment. `pptx-import.ts` records source layout/master/theme paths, placeholder source IDs/geometry provenance, and nested group IDs. `model.ts` adds optional versioned text/source fields so previous snapshots remain parseable. Source metadata describes the imported baseline; direct edited values remain on `SlideElement`. It is not an editable master scene graph.

`slide-text.ts` projects retained run styles through paragraph-local text splices and whole-object overrides without modifying original runs. `SlideText.svelte` is shared by the canvas, thumbnails and slideshow. The active inline textarea remains plain text; this is not rich selection editing or native caret layout. `pptx-preserve.ts` patches the original XML and materializes an inherited transform only when needed. `presentation-migration.ts` runs on workspace hydration, backup import and export; it preserves distinct edits and original bytes. The frozen legacy text projection is intentional migration code, not an alternate product engine.

The existing first-notes browser workflow in `tests/pptx-fidelity.spec.ts` now checks history, reload, the notes-master relationship and downloaded reimport. `src/pptx-edit.test.ts` verifies registration, a separate unchanged theme payload, reuse across two notes slides and broken-theme rejection. `scripts/verify-powerpoint-edits.ps1` validates the actual combined image/notes export; it prints each filename before opening it so failures identify the specific artifact.

Existing bounds remain: 500 slides/objects per slide, 100,000 text characters, retained ZIP complexity checks, 100 group ancestors. Latin inheritance is a bounded first resolver: complex scripts, default paragraph-property edge cases, full body/style inheritance, native bullets/fields, autofit, margins, vertical alignment, line shaping and general group transforms require further contracts. Large-workload measurements and off-thread execution remain pending. Extra empty paragraphs and full cross-paragraph rich edits require separate native acceptance.

## Nested group transform subset

Native fixture `tests/fixtures/powerpoint-groups.pptx` contains four slides with two nested group levels. The inner group is scaled 1.5 on both axes and translated; the outer group is scaled 2 horizontally and 1.5 or 2 vertically and translated. Slide 3 additionally rotates the outer group 30 degrees; slide 4 flips it horizontally. The three leaves are two solid rectangles and an ellipse, without text, images or outlines. `native-powerpoint-groups.json` binds the source bytes and records native grouped and independently ungrouped frames; both native measurements agree for all 12 leaves.

[Microsoft's group transform documentation](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.transformgroup) identifies child offsets/extents and center-based flips. The implementation composes each child-coordinate mapping from the outer group inward. Rotation uses 60,000 units per degree as recorded in the native files; the older API remarks' 64,000 wording is not used as an oracle. Research date: September 10, 2026.

`pptx-group-transform.ts` stores a bounded affine parent matrix plus original local frame in `sourceGroupTransform`. Orthogonal effective frames map to the existing positioned-object renderer. Non-orthogonal frames retain their original source, carry `projected: false`, display an explicit conversion note and reject geometry editing. This is not a full shear renderer or complete scene graph. An omitted optional group transform is identity; present zero/negative child extents and nonfinite/singular matrices reject.

For the editable subset, the first native leaf moves +12pt/+9pt and grows +12pt/+9pt through independent PowerPoint setters. Browser edits use +16/+12/+16/+12 units. The retained writer derives its inverse matrix from the freshly imported original, never from editable backup metadata. Only that leaf's local transform is patched; other package payloads and group containers are preserved. Installed PowerPoint reopens the browser download and compares all 12 leaf IDs, positions, extents and rotations with the independent edit. All four native-rendered slides compare exactly at 144 DPI. This certifies exported-file rendering for this fixture, not native group-selection UI or all browser pixels.

The browser workflow checks 12 rendered frames (one Chromium layout unit, 1/64 CSS pixel, plus 0.001 serialization tolerance; model/native unit assertions use 0.0005 browser units). It checks rejection of a flipped-group move, valid child move/resize, Undo/Redo, saved reload, slideshow, byte-identical unchanged export and actual edited export/reimport. A second workflow seeds old IndexedDB group-local coordinates, verifies corrected display, original export bytes and unchanged storage revision. Unit cases also retain distinct legacy edits, reject singular transforms, and report skewed groups without modifying source bytes.

`groupModelVersion: 1` makes migration additive. `presentation-migration.ts` selects the correct old text/group projection independently, replaces only values still equal to the old projection, and retains distinct edits. The historical ambiguity of explicit edits equal to an old default remains; this migration does not infer unrecorded user intent.

The first full corpus run caught a regression in `sample_pptx_grouping_issues.pptx`: its small integer child units were being clamped to 10 display units before applying a large group scale. Import now uses the actual positive local extents before projection; a coordinate-unit rescaling regression verifies the same native-measured frames. The model's 2,000-unit size bound remains intact. Coarse integer coordinate systems can also make a requested fractional edit unrepresentable. Retained export rejects changed coordinates whose rounding would move the effective frame by more than 0.001 browser units, leaving source bytes intact. Renormalizing those group coordinate systems remains future work; this export-only precision guard is separate from the editor's rotated/flipped/text guard.

Remaining boundaries: editing rotated/reflected groups, nonuniform-scale/rotation shear, coarse-coordinate renormalization, group creation/ungrouping, child reordering, native selection semantics, grouped text scaling and outlines, arbitrary shape geometry, degenerate leaf extents, master authoring and full text layout. These are retained in the open P-DRAW/P-MASTER/P-TEXT requirements.
