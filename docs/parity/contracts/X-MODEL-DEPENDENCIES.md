## Behavioral specification

1. Data!A1=2, Data!B1=A1*3, Summary!A1=Data!B1+1, Summary!B1=2+2. After editing Data!A1 to 5, intermediate/dependent results change 6→15 and 7→16. The unrelated result stays 4 and its memoized evaluation is retained.
2. Undo restores 2/6/7, redo restores 5/15/16; reload reconstructs correct results from saved semantic cells. The actual downloaded workbook reimports with those results and reopens/recalculates identically in native Excel.
3. A referenced empty cell becoming nonempty invalidates aggregates and cached division errors. Conditional dependencies follow the executed branch; editing a no-longer-read branch does not recompute the conditional result.
4. Named definitions, table/filter metadata, sheet identities/order and occupied extents conservatively reset value/error caches. Cell edits inside unchanged extents invalidate observed transitive consumers. Deleting/replacing a formula or changing text/error typing invalidates its cached result.
5. Shared lookup searches skip some repeated reads. All owners of those shortcuts and their dependents are therefore invalidated on any cell edit until lookup-cache provenance is modeled. A changed earlier search key must not leave a second VLOOKUP stuck on a cached row.
6. Cycle traversal terminates. Breaking a cycle allows a later revision to calculate correctly. Exceeding the observed-edge budget disables cache reuse on the next revision rather than trusting an incomplete graph.

## Model and implementation

`formula-dependencies.ts` maintains precedent and dependent sets by stable sheet ID plus normalized cell address, with a 100,000-edge bound. `formulas.ts` records actual cell reads, including blank/aggregate checks, before memoized lookup; clears old edges when a formula recalculates; retains parsed expressions in a bounded 4,096-entry cache; and exposes `update` for immutable workbook revisions. Existing value/error/unsupported result distinctions remain in place.

`SheetEditor.svelte` owns one calculator per editor and updates it on workbook revisions. Each update returns a new callable identity so Svelte can observe a cross-sheet change even when the visible sheet object's identity stays the same. Dependency caches are transient, never stored in OOXML or IndexedDB. Saved snapshots and original bytes remain unchanged by calculation. `diagnostics()` supports cache-behavior tests; it is not a product control.

The update API requires immutable snapshots, matching existing editor transactions. Revision comparison still scans cells/extents and metadata; this is not a completed large-workbook performance engine. Unsupported functions, dynamic arrays, asynchronous/volatile calculation modes, worker cancellation and precise static reference identities remain gaps. Existing recursion/read bounds and source-preserving export guards remain.
