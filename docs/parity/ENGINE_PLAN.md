# Engine work order and migration decisions

This is the target architecture and executable work queue. It does not claim the proposed engines already exist. Retain Svelte 5/SvelteKit/adapter-static and local bundled dependencies. Existing partial features remain usable while their internals are extended behind tested interfaces.

## Decisions

| Layer            | Existing foundation                                        | Required change                                                                                                                     | Migration gate                                                                                  |
| ---------------- | ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Document core    | model.ts; immutable snapshots and retained source parts    | Explicit versioned semantic nodes, stable IDs, typed commands, source mapping and loss annotations                                  | Old backups migrate, unrelated source parts survive, undo stays atomic                          |
| Word             | Tiptap/ProseMirror and supported DOCX patching             | Section-aware document/layout model, pagination and shaping, anchors/fields/review semantics; editor selection mapped to layout     | Same fixtures through old and new paths; native page/run/geometry assertions                    |
| Excel            | Sparse grid, bounded scalar calculator and retained writer | Parsed formula representation, dependency graph and worker scheduling; array values; complete tables/rules/charts/pivots/data model | Typed native results, relative/name repair, recalc invalidation, cancellation and export caches |
| PowerPoint       | Positioned text/shapes/images and source layers            | Scene graph with rich runs, groups, inherited master/layout properties and animation timing graph                                   | Native transforms, text layout, layer identities and playback events                            |
| Storage          | IndexedDB revisions and transaction completion             | Asset store abstraction; evaluate OPFS for large blobs; recoverable commands/checkpoints and migrations                             | Crash/quota/conflict tests; no weaker persistence guarantees                                    |
| Execution        | Main-thread commands and browser parsing                   | Worker protocols with request IDs, revision checks, cancellation and bounded memory; benchmark any WASM candidate                   | Offline static build, stale results discarded, responsive UI under large workloads              |
| Rendering/output | DOM/SVG and existing Office writers                        | Shared semantic measurements for editor/print/export; explicit fallback geometry                                                    | Exact-font native visual comparisons plus semantic assertions                                   |

No dependency is adopted solely because it can open DOCX/XLSX/PPTX. Evaluate its editable model, source-preservation behavior, browser/offline support, API stability, tests, bundle/memory cost and distribution terms. Document and benchmark candidates before replacing a working subsystem. Wasm is an execution option, not a ready-made Office engine. Review transitive assets/licenses against the MIT distribution plan; do not assume Microsoft fonts or reference_repo source can be redistributed.

The reference repo's `src/lib/functions/saveData/indexedDb.ts` and static Svelte configuration demonstrate local transaction completion and client-side architecture. They remain inspiration; do not copy MPL implementation into MIT files. Noffice's existing stale-revision checks must survive any storage redesign.
